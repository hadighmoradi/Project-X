# Contributing to Project X

Thank you for your interest in Project X. Contributions are welcome, provided that they respect the project's technical and licensing boundaries.

## Before opening a pull request

- Describe the change and its purpose.
- Include the relevant source revision, host toolchain, command, and test scope when reporting engineering results.
- Do not describe a roadmap item or a limited probe as a generally supported feature.
- Do not include third-party code, assets, generated files, or copied documentation unless you have the right to submit them and their license is compatible. Preserve all required notices.

## License of contributions

- Code, tests, development tools, build scripts, and project-owned source fixtures are accepted under **GPL-3.0-or-later**.
- Project documentation and website content are accepted under **CC BY-SA 4.0**.
- Standalone examples use GPL-3.0-or-later by default. An example is MIT-licensed only when that individual file explicitly declares MIT.
- Contributors retain copyright in their own work. The project does not currently require a copyright assignment or Contributor License Agreement (CLA). A contribution must nevertheless be submitted with the rights needed for distribution under the applicable project license.
- Do not assume that the planned LGPL runtime policy or X Runtime Linking Exception applies to contributions today. Runtime contributions will need a separately published policy before that component is accepted or distributed.

## Generated programs

The compiler's GPL license does not automatically make every independently written program compiled with it GPL-licensed. Programs that bundle runtime code, templates, or other project material need a separate license review.

## Current boundaries

The compiler is experimental. Please keep claims tied to the exact implementation and tests demonstrated by the relevant checkpoint. General edge insertion remains disabled unless a later checkpoint explicitly proves it is safe.

# مشارکت در Project X

از علاقهٔ شما به مشارکت در Project X سپاسگزاریم. از پیشنهادها و مشارکت‌ها استقبال می‌کنیم، به شرط آنکه محدودهٔ فنی و مجوزهای پروژه رعایت شود.

## پیش از ارسال Pull Request

- تغییر و دلیل انجام آن را توضیح دهید.
- هنگام گزارش نتیجهٔ مهندسی، revision سورس، ابزار زنجیرهٔ میزبان، فرمان اجرا و محدودهٔ آزمون را بنویسید.
- یک قابلیت در نقشهٔ راه یا نتیجهٔ یک آزمایش محدود را به‌عنوان قابلیت عمومی و کامل معرفی نکنید.
- کد، تصویر، فایل تولیدشده یا مستندات شخص ثالث را بدون داشتن حق استفاده و بررسی سازگاری مجوز آن وارد نکنید. اعلان‌های حقوقی لازم باید حفظ شوند.

## مجوز مشارکت‌ها

- کد، آزمون‌ها، ابزارهای توسعه، اسکریپت‌های ساخت و fixtureهای سورس متعلق به پروژه تحت **GPL-3.0-or-later** پذیرفته می‌شوند.
- مستندات و محتوای وب‌سایت پروژه تحت **CC BY-SA 4.0** پذیرفته می‌شوند.
- مثال‌های مستقل به‌طور پیش‌فرض GPL-3.0-or-later هستند. فقط فایلی که صریحاً MIT را اعلام کند، تحت MIT خواهد بود.
- مشارکت‌کنندگان مالکیت حقوقی آثار خود را حفظ می‌کنند. در سیاست فعلی پروژه، انتقال کپی‌رایت یا امضای توافق‌نامهٔ CLA لازم نیست؛ با این حال، مشارکت‌کننده باید حق ارائه و انتشار اثر خود تحت مجوز مربوط به همان بخش را داشته باشد.
- تصور نکنید سیاست LGPL برای Runtime یا استثنای اتصال X که برای آینده در نظر گرفته شده، اکنون شامل مشارکت‌ها می‌شود. پیش از پذیرش یا انتشار Runtime باید سیاست جداگانهٔ آن اعلام شود.

## برنامه‌های تولیدشده

GPL بودن کامپایلر به‌تنهایی باعث نمی‌شود هر برنامهٔ مستقلی که با آن نوشته و کامپایل شده است، GPL شود. برنامه‌هایی که کد Runtime، template یا بخش دیگری از محتوای پروژه را همراه خود دارند، به بررسی جداگانهٔ مجوز نیاز دارند.

## محدودهٔ فنی فعلی

کامپایلر هنوز آزمایشی است. لطفاً ادعاهای فنی را به پیاده‌سازی و آزمون‌هایی محدود کنید که در checkpoint مربوطه واقعاً نشان داده شده‌اند. درج عمومی edge تا زمانی که یک checkpoint بعدی ایمنی آن را ثابت نکند، غیرفعال باقی می‌ماند.

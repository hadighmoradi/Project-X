# زبان برنامه‌نویسی X

### یک زبان و ابزار زنجیرهٔ native در مرحلهٔ آزمایشی

**C++17** · **CMake** · **x64 (x86-64)** · **نقشهٔ راه Windows/Linux؛ macOS در آینده**

<a href="README.md">English</a>

</div>

این پروژه را با هدف ساخت یک زبان کامپایل‌شوندهٔ native و ابزارهایش شروع کردم. این snapshot شامل **Native Frontend v1.48.0** است؛ کار هنوز ادامه دارد و محصول نهایی آمادهٔ استفادهٔ تولیدی نیست.

## آنچه در این snapshot وجود دارد

- frontend با C++17 و مسیر جاری code generation بومی x64 (x86-64).
- اجرای parsing با `parse_source`؛ تابع `compile_x64_coff_program`، `CompilationUnit`های از پیش parse‌شده را می‌گیرد.
- تولید ماژول‌های COFF برای Windows x64 و link plan قطعی؛ linker پلتفرم PE نهایی را می‌سازد.
- هدف‌های build با CMake و مجموعهٔ گسترده‌ای از regression testها.

## نقشهٔ پلتفرم‌ها و پشتیبانی واقعی

هدف من پشتیبانی از **x86-32 (X32) و x86-64 (X64)** روی Windows و Linux است؛ macOS را برای مرحله‌ای بعد در نظر دارم. این نقشهٔ راه است و به معنی پیاده‌سازی همهٔ هدف‌ها در کد فعلی نیست.

| هدف | شواهد در workspace فعلی |
|---|---|
| Windows x64 (x86-64) | مسیر کامپایل پیاده‌سازی شده است: `compile_x64_coff_program` شیءهای AMD64 COFF و link plan تولید می‌کند و linker پلتفرم executable از نوع PE32+ را می‌سازد. |
| Linux x64 (x86-64) | اجزای ELF64 و شواهد محدود LLD روی میزبان Linux وجود دارند؛ API جاری یک مسیر کامل از سورس تا ELF بومی را اثبات نمی‌کند. |
| X32 (x86-32) | هدف نقشهٔ راه است؛ مدل target و backend فعلی مسیر code generation برای x86 سی‌ودوبیتی ارائه نمی‌کنند. منظور از X32 در اینجا x86 سی‌ودوبیتی است، نه Linux x32 ABI. |
| macOS | هدف آینده است. بخشی از metadata هدف مدل شده، اما workspace فعلی Mach-O را serialize نمی‌کند و اعتبارسنجی روی macOS را ثابت نکرده است. |

«AMD64» نام فنی رایج معماری x86-64 و نام machine type در COFF مسیر فعلی Windows است؛ محدودشدن پروژه به پردازنده‌های AMD را معنی نمی‌دهد. قابلیت build شدن روی یک میزبان با پشتیبانی از تولید خروجی برای آن پلتفرم یکسان نیست.

## انگیزهٔ ساخت و انتخاب نام

این پروژه را شروع کردم چون دلم می‌خواهد برنامه‌ها سریع اجرا شوند و فایل خروجی کوچکی داشته باشند، اما نوشتن کد با زبان هم سخت نباشد. compiler هنوز آزمایشی است؛ این‌ها هدف‌هایی هستند که باید کم‌کم به آن‌ها برسیم، نه نتیجه‌ای که همین امروز ادعا کنم.

فعلاً اسم پروژه را **X** گذاشته‌ام. اسم نهایی باز است و دوست دارم کسانی که پروژه را دنبال می‌کنند پیشنهاد بدهند، دربارهٔ اسم‌ها حرف بزنیم و بعد به گزینه‌های نهایی رأی بدهیم. مخزن هنوز عمومی نیست و بخش Discussions فعال نشده؛ پس پیشنهادها و رأی‌گیری هنوز شروع نشده‌اند. وقتی مخزن عمومی و بخش گفت‌وگو آماده شد، پیوند مستقیم را اضافه می‌کنم. [چشم‌انداز و روند انتخاب نام](docs/PROJECT_VISION_AND_NAMING_FA.md)

## checkpoint جاری

**N113-G62R16 · ۲۳ نوامبر ۲۰۲۶**

| بخش | وضعیت |
|---|---|
| سلامت سورس | هر ۱۴ فایل snapshot مرحلهٔ G62R16 با workspace زنده تطبیق دارند. |
| probe محدود | G62R13 با MSVC و G2-on روی workload کنترل‌شده PASS شد: ۵۶ action، ۶۶ machine move و ۴۷۴ بایت انتقال. |
| درج عمومی edge | آماده نیست؛ G11 برابر ۰ از ۷ است و insertion انجام نشده. |
| Full Regression | برای این checkpoint اجرا نشده است. |
| گام بعد | G62R17: بررسی liveness موقت‌های expression و مالکیت register پیش از طراحی routing اختیاری. |

این نتایج فقط به همان بررسی‌های مشخص محدودند. شمار inventory ثبت‌شده در CMake به معنی تعداد آزمون‌های اجراشده نیست.

## معماری

```text
سورس X
  │
  ▼
parse_source ──► CompilationUnit
                    │
                    ▼
       compile_x64_coff_program
                    │
                    ▼
       ماژول‌های AMD64 COFF و link plan
                    │
                    ▼
             linker پلتفرم
```

backend جاری پیاده‌سازی اختصاصی x64 (x86-64) است و LLVM نیست. مسیر Windows از COFF با machine type فنی AMD64 استفاده می‌کند و linker پلتفرم executable نهایی را می‌سازد. تفاوت پشتیبانی موجود و نقشهٔ راه در جدول بالا آمده است.

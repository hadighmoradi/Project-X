# روش توسعهٔ Project X

می‌خواهیم روند پیشرفت پروژه روشن و قابل پیگیری باشد. هر مرحله‌ای که به پایان می‌رسد باید در کد، آزمون‌ها، مستندات و صفحه‌های عمومی پروژه به‌درستی ثبت شود.

## پیش از اعلام پایان یک مرحله

- revision دقیق سورس و بخش‌هایی را که تغییر کرده‌اند ثبت کنید.
- سیستم‌عامل، کامپایلر، ابزارها و تنظیمات Build را بنویسید.
- فرمان‌ها و آزمون‌هایی را که واقعاً اجرا شده‌اند فهرست کنید.
- مشخص کنید چه مواردی موفق، ناموفق یا اصلاً آزمایش‌نشده بوده‌اند.
- محدودیت‌های باقی‌مانده و گام بعدی را توضیح دهید.

## وضعیت هر قابلیت را روشن بنویسید

در مستندات از این برچسب‌ها استفاده می‌کنیم:

- **Planned – برنامه‌ریزی‌شده:** قابلیتی که دوست داریم در آینده بسازیم.
- **Designed – طراحی‌شده:** ایده و قواعد آن نوشته شده، اما شاید هنوز پیاده‌سازی نشده باشد.
- **Prototype – نمونهٔ اولیه:** نسخه‌ای آزمایشی وجود دارد، ولی برای استفادهٔ عمومی آماده نیست.
- **Implemented – پیاده‌سازی‌شده:** قابلیت در سورس پروژه وجود دارد.
- **Verified – اعتبارسنجی‌شده:** آزمون‌های مشخص در محیط ثبت‌شده با موفقیت انجام شده‌اند.
- **Blocked – متوقف:** بخشی که برای ادامه لازم است هنوز آماده نیست.
- **Not tested – آزمایش‌نشده:** هنوز آزمونی برای آن مورد اجرا نشده است.

وجود یک نمونه کد در سند طراحی، به معنی پشتیبانی کامپایلر از آن نیست. موفقیت یک آزمایش محدود هم ثابت نمی‌کند که همهٔ حالت‌ها درست کار می‌کنند.

## مستندات پروژه را به‌روز نگه داریم

پس از پایان و بررسی هر مرحله، سندهای مرتبط را به‌روز می‌کنیم:

- docs/STATUS.md برای وضعیت فعلی و گام بعدی؛
- docs/DEVELOPMENT_HISTORY_FA.md برای ثبت مرحله‌های تکمیل‌شده؛
- docs/ARCHITECTURE.md یا صفحه‌های طراحی زبان، هر وقت تصمیمی در طراحی تغییر کند؛
- مستندات آزمون و README، اگر روش ساخت، آزمون یا توضیحات عمومی تغییر کرده باشد.

تا جای ممکن نسخهٔ انگلیسی و فارسی را هم‌زمان به‌روز می‌کنیم.

## انتشار نتیجه

نتیجهٔ هر مرحلهٔ تکمیل‌شده با یک commit روشن در GitHub ثبت می‌شود. برای تغییرات بزرگ‌تر، یک شاخه و Pull Request جداگانه می‌سازیم. لینک آزمون‌ها و مستندات مرتبط را هم قرار می‌دهیم تا دیگران بتوانند نتیجه را دنبال کنند.

سوابق و نتایج آزمون‌های قبلی را نگه می‌داریم. نتیجهٔ جدید نباید جای سابقهٔ قبلی را بگیرد؛ نتیجهٔ تازه را اضافه می‌کنیم و تفاوت آن را توضیح می‌دهیم.

## قانون اصلی

یک مرحله زمانی تمام‌شده است که کار بررسی شده باشد، نتیجه و محدودیت‌هایش ثبت شده باشند، مستندات مرتبط به‌روز شده باشند و تغییرات آن در GitHub منتشر شده باشند.

# چشم‌انداز Project X و انتخاب نام

Project X را با یک خواسته شروع کردم: زبانی داشته باشیم که نوشتن برنامه با آن ساده باشد، خروجی Native بسازد و بتواند فایل اجرایی کم‌حجمی تولید کند.

می‌خواهیم راحتی زبان‌های سطح‌بالا را با قدرت و کنترل زبان‌های Native کنار هم بیاوریم. کدهای روزمره باید خوانا باشند، اما برای کارهای سیستمی هم دست برنامه‌نویس باز بماند.

این‌ها هدف‌های پروژه‌اند. کامپایلر هنوز آزمایشی است؛ بنابراین سرعت، اندازهٔ فایل اجرایی و سادگی کار باید در ادامه و با آزمون‌های واقعی سنجیده شوند.

## از چه زبان‌هایی الهام می‌گیریم؟

در طراحی X به چند زبان و ابزار نگاه کرده‌ایم:

- از **Visual Basic** خوانایی و سادگی نحو را دوست داریم.
- از **C** کنترل Native و دسترسی نزدیک به سیستم را می‌خواهیم؛ C همچنین معیار مقایسهٔ سرعت است.
- از **Delphi و Lazarus** محیط توسعه و طراحی بصری فرم‌ها را الگو می‌گیریم.
- از **Python** راحتی انجام کارهای روزمره و APIهای روشن را بررسی می‌کنیم.
- از **Rust** دقت در نوع‌ها، خطاها و مدیریت منابع را دنبال می‌کنیم.
- از **Windows Batch** سادگی دستورهای فایل و کارهای سیستمی را می‌گیریم.
- از **PureBasic** تجربهٔ سادهٔ ساخت برنامه‌های گرافیکی را بررسی می‌کنیم.

هدف این است که نکته‌های خوب هرکدام را کنار هم بگذاریم و زبانی بسازیم که هویت خودش را داشته باشد.

برای دیدن نمونه کدها و وضعیت کامپایلر، [صفحهٔ معرفی طراحی زبان](../language-design.html#fa) را ببینید.

## برای نام زبان پیشنهاد بدهید

فعلاً X فقط نام موقت پروژه است. دوست دارم نام نهایی با مشارکت کسانی انتخاب شود که پروژه را دنبال می‌کنند و از آن استفاده خواهند کرد.

نامی به ذهنتان رسیده است؟ در بخش [Ideas](https://github.com/hadighmoradi/Project-X/discussions/categories/ideas) یک گفت‌وگوی جدا برای آن باز کنید و بنویسید چرا این نام را دوست دارید. بعد از بررسی پیشنهادها، چند گزینه را در بخش [Polls](https://github.com/hadighmoradi/Project-X/discussions/categories/polls) به رأی می‌گذاریم.

نامی که هنگام پایان نظرسنجی بیشترین رأی را داشته باشد، نام جدید پروژه خواهد شد.

## پلتفرم‌ها

هدف بلندمدت، پشتیبانی از x86-32 و x86-64 روی Windows و Linux است. پشتیبانی از macOS را برای مرحله‌ای بعد در نظر گرفته‌ایم.

اما کامپایلر عمومی فعلی هنوز محدودتر است:

| پلتفرم | وضعیت فعلی |
|---|---|
| Windows x64 | مسیر یکپارچه، ماژول‌های AMD64 COFF و link plan می‌سازد؛ linker ویندوز PE32+ تولید می‌کند |
| Linux x64 | بخش‌هایی از ELF64 و آزمون‌های محدود LLD وجود دارند، اما مسیر کامل سورس تا ELF اثبات نشده است |
| x86-32 | در نقشهٔ راه است، اما در backend فعلی پیاده‌سازی نشده |
| macOS | هدف آینده است؛ خروجی Mach-O و اعتبارسنجی روی macOS آماده نیست |

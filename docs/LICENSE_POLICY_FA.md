# سیاست مجوزهای Project X

این صفحه سیاست فعلی مجوزها را توضیح می‌دهد و آن را از برنامه‌هایی که هنوز اجرا یا منتشر نشده‌اند جدا می‌کند.

## مجوز هر بخش

| بخش | سیاست فعلی |
|---|---|
| کامپایلر، backend، کتابخانه‌های پروژه، آزمون‌ها، ابزارهای توسعه، اسکریپت‌های ساخت و fixtureهای سورس متعلق به پروژه | GPL-3.0-or-later |
| مستندات و محتوای وب‌سایت پروژه | CC BY-SA 4.0 |
| مثال‌های مستقل | به‌طور پیش‌فرض GPL-3.0-or-later؛ فقط در صورتی MIT هستند که خود فایل صریحاً همین مجوز را اعلام کند |
| کتابخانهٔ Runtime | برنامهٔ آینده: LGPL-3.0-or-later همراه با X Runtime Linking Exception؛ در این snapshot وجود ندارد |
| اجزای شخص ثالث | تابع مجوزها و اعلان‌های حقوقی خودشان هستند |

## چه چیزهایی اکنون در مخزن وجود دارد؟

فایل ریشهٔ [LICENSE](../LICENSE) متن استاندارد GNU GPL نسخهٔ ۳ را دارد. فایل‌های کد متعلق به پروژه باید با اعلان SPDX مشخص کنند که تحت **GPL-3.0-or-later** ارائه شده‌اند. متن مجوز مستندات در [LICENSES/CC-BY-SA-4.0.txt](../LICENSES/CC-BY-SA-4.0.txt) قرار دارد. محدودهٔ هر بخش نیز در [COPYRIGHT.md](../COPYRIGHT.md) خلاصه شده است.

سیاست Runtime فعلاً فقط یک برنامه برای آینده است. این snapshot هیچ پیاده‌سازی Runtime و هیچ متن نهایی برای استثنای اتصال X ندارد. پیش از انتشار Runtime باید متن استثنا تهیه و بررسی شود. این متن باید شرایط اتصال ایستا و پویا، امکان اتصال مجدد، تغییر Runtime و توزیع آن را روشن کند. تا پیش از آن، هیچ فایلی در این snapshot نباید مشمول آن استثنا فرض شود.

## برنامه‌هایی که با Project X کامپایل می‌شوند

GPL بودن کامپایلر به‌تنهایی باعث نمی‌شود هر برنامه‌ای که کاربر با آن می‌نویسد، خودبه‌خود GPL شود. مجوز خروجی به محتوای آن و این موضوع بستگی دارد که آیا کد دارای حق نشر پروژه، مانند Runtime یا templateها، در آن گنجانده شده یا از آن مشتق شده است. اجزای همراه برنامه و محتوای تولیدشده باید جداگانه بررسی شوند.

## مشارکت در پروژه

مشارکت‌کنندگان مالکیت حقوقی کد و نوشته‌هایی را که خودشان ایجاد کرده‌اند حفظ می‌کنند. با ارسال یک مشارکت برای ورود به پروژه، فرد باید حق ارائهٔ آن را تحت مجوز همان بخش داشته باشد: کد تحت GPL-3.0-or-later و مستندات پروژه تحت CC BY-SA 4.0. طبق سیاست فعلی پروژه، انتقال کپی‌رایت یا امضای CLA لازم نیست. این سیاست به معنی اجازهٔ تغییر یک‌طرفهٔ مجوز آثار سایر مشارکت‌کنندگان نیست.

برای مشارکت در Runtime آینده یا استثنای اتصال آن، پیش از پذیرش مشارکت‌ها باید سیاست جداگانه و صریحی تعیین شود. راهنما در [CONTRIBUTING.md](../CONTRIBUTING.md) قرار دارد.

## محتوای شخص ثالث و بررسی‌های پیش از انتشار

کد، فایل باینری، محتوای تولیدشده یا مطالب کپی‌شده از منابع دیگر باید اعلان‌ها و شرایط مجوز اصلی خود را حفظ کنند و از نظر سازگاری بررسی شوند. تهیهٔ فهرست کامل وابستگی‌ها، بررسی سازگاری مجوزها و ممیزی اعلان‌های حقوقی هنوز از کارهای لازم پیش از انتشار است. وجود این صفحه به معنی گذراندن آن ممیزی نیست.

این صفحه خلاصهٔ سیاست پروژه است و جایگزین مشاورهٔ حقوقی نیست.

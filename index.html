The reason behind the project

Why create another language?

I started this project because I want one language to combine fast execution, small native programs, and code that is easy to write.

01

Fast execution

I want programs to run quickly. Benchmarks will show how close the compiler gets.

02

Small native programs

I want the native output to stay small, with little extra overhead for lightweight programs.

03

Simple to write

Everyday code should be clear and straightforward. I do not want speed to make it difficult to read or write.

These are the things I want to get right. The compiler is still experimental; we will need real programs and measurements to see how close it gets.

A community decision

Help give the language a name

“X” is just a placeholder for now. I would like people to suggest names, talk through the ideas, and vote on a shortlist.

The repository is public and Discussions are open. Add one name idea per discussion in Ideas and briefly explain why it fits. After the community has discussed the suggestions, I will shortlist candidates and open a poll in Polls. The name with the most votes when the poll closes will replace X.

1SuggestOpen one discussion for a candidate and briefly explain its meaning or inspiration.

What works today

Roadmap and current support

My roadmap is x86-32 and x86-64 for Windows and Linux, with macOS later. The current compiler is only part of that plan.

Current integrated path

Windows x64

Compiler API emits AMD64 COFF objects and a link plan; a platform linker creates the PE32+ executable.

Partial components

Linux x64

ELF64 components and scoped Linux-host LLD evidence exist. A full source-to-ELF path is not established.

Roadmap

X32 · x86-32

Planned target, but 32-bit x86 code generation is not implemented in the current target model/backend.

Future

macOS

Some target metadata is modeled; Mach-O output and macOS validation are not established.

AMD64 is the technical name used for the Windows x64 COFF path. It does not mean the project is limited to AMD processors.

۱

اجرای سریع

می‌خواهم برنامه‌ها سریع اجرا شوند؛ باید با اندازه‌گیری ببینیم چقدر به این هدف نزدیک می‌شویم.

۲

فایل اجرایی کوچک

دلم می‌خواهد فایل اجرایی native کوچک باشد و برای برنامه‌های سبک سربار اضافه نداشته باشد.

۳

کدنویسی ساده

کد روزمره باید روشن و سرراست باشد؛ ساده‌نویسی را فدای سرعت نمی‌کنم.

این‌ها خواسته‌های من‌اند، نه نتیجه‌ای که compiler فعلی ثابت کرده باشد. باید با برنامه‌های واقعی و اندازه‌گیری ببینیم چقدر به سرعت، خروجی کوچک و کدنویسی ساده نزدیک می‌شویم.

انتخاب با مشارکت جامعه

برای زبان نام پیشنهاد بدهید

هنوز اسم نهایی را انتخاب نکرده‌ام؛ فعلاً در پروژه صدایش می‌کنیم X. دوست دارم جامعه اسم پیشنهاد بدهد، درباره‌شان حرف بزنیم و بعد رأی بدهیم.

مخزن عمومی است و Discussions فعال شده. پیشنهادها را در دستهٔ Ideas ثبت کنید؛ برای هر نام یک گفت‌وگوی جدا بسازید و دلیل انتخاب را کوتاه بنویسید. پس از گفت‌وگو و کوتاه‌فهرست‌کردن گزینه‌ها، نظرسنجی را در دستهٔ Polls باز می‌کنم. نامی که هنگام بسته‌شدن رأی‌گیری بیشترین رأی را داشته باشد، جای X را می‌گیرد.

وضعیت واقعی

نقشهٔ راه و پشتیبانی فعلی

هدف من پشتیبانی از x86-32 و x86-64 روی Windows و Linux است؛ macOS را برای آینده در نظر دارم. کد فعلی فقط بخشی از این مسیر است.

مسیر فعلی

Windows x64

API کامپایل شیء AMD64 COFF و link plan می‌سازد؛ linker پلتفرم PE32+ را تولید می‌کند.

اجزای محدود

Linux x64

اجزای ELF64 و شواهد محدود LLD موجودند؛ مسیر کامل سورس تا ELF اثبات نشده است.

نقشهٔ راه

X32 · x86-32

هدف آینده است؛ code generation سی‌ودوبیتی در backend فعلی پیاده‌سازی نشده.

آینده

macOS

metadata تا حدی مدل شده؛ خروجی Mach-O و اعتبارسنجی آن هنوز اثبات نشده است.

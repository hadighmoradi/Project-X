A language taking shape

Simple to write.
Native by design.

I want X to feel comfortable to write, run as a native program, and create executables that stay small. Here is the direction, the ideas behind it, and where the project stands today.

01 · What matters

What I want X to be good at

The goal is to make everyday programming easy without giving up native speed, small output, or control over system resources.

01

Easy to read

Code should be clear and familiar. Simple jobs should take only a few straightforward lines.

02

Fast native programs

Programs should compile to native output. We will compare performance with equivalent C and C++ programs.

03

Small executables

A program should bring only the runtime and library parts it actually needs.

02 · Design ideas

Good ideas can come from different places

I have looked at languages and tools that do different things well. We can learn from each one and still give X its own style.

Visual Basic — simplicity

I like its friendly, readable style. X should make common code feel just as approachable.

C — native control

C is a useful reference for native performance and systems access. Speed will be measured, not assumed.

Delphi and Lazarus — development tools

Their integrated IDEs and visual form designers are a model for the tools I would like X to have.

Python — everyday simplicity

Clear high-level APIs can make common tasks easier without making the language depend on a dynamic interpreter.

Rust — careful resource handling

Type safety, clear errors, and predictable resource ownership are important ideas to learn from.

Windows Batch and PureBasic

Batch keeps common system tasks direct; PureBasic shows how GUI programming can feel approachable.

03 · Speed and file size

Small output comes from engineering choices

We are not taking small executable size from one particular language. It depends on how the compiler, linker, and libraries work together.

Native compilation

Programs are intended to run directly on the target system, without needing a separate language interpreter.

Modular runtime

Only the library pieces used by a program should be included in its output.

Measure the result

We need repeatable tests for executable size, startup time, and performance. Static linking alone does not guarantee a small file.

04 · Code style

A quick look at X syntax

The current syntax reference uses UTF-8 .src files, braces for blocks, semicolons at the end of statements, and the function keyword.

A function

function Add(left, right) {
    return left + right;
}

A condition

if (ready) {
    PrintLine "Ready";
} else {
    PrintLine "Please wait";
}

A form description

Form MainForm {
    Caption = "Customer List";
    ClientWidth = 700;
    ClientHeight = 450;

    Button SaveButton {
        Caption = "Save";
        OnClick = HandleSave;
    }
}

The .frm file describes the form; the matching .src file contains the code and event handlers. The visual designer and its full compiler integration are still being developed.

۰۳ · سرعت و حجم

خروجی کم‌حجم با انتخاب‌های مهندسی

کم‌حجم بودن را از زبان خاصی کپی نمی‌کنیم. این موضوع به روش کار کامپایلر، linker و کتابخانه‌ها بستگی دارد.

کامپایل Native

برنامه مستقیم روی سیستم مقصد اجرا شود و برای هر برنامه به مفسر جدا نیاز نباشد.

Runtime ماژولار

فقط بخش‌هایی از کتابخانه وارد خروجی شوند که برنامه واقعاً استفاده می‌کند.

اندازه‌گیری واقعی

حجم فایل، زمان شروع و سرعت اجرا باید با آزمون‌های تکرارپذیر سنجیده شوند. Static Linking به‌تنهایی کافی نیست.
